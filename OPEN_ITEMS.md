# Cross-Project Open Items

A single index of every genuinely open question, pending decision, or blocked task currently scattered across the various `CONTEXT.md` files in this repo. This file does **not** replace those entries — it points back to them. When an item here gets resolved, update its status below, but write the actual resolution detail in the originating `CONTEXT.md`'s session log (consistent with how every other decision in this repo is recorded).

Each item is tagged with one of:
- **[Bug]** — a newly-identified code defect, confirmed (by direct tracing and/or execution) to produce an incorrect result. Needs an actual code fix, not just a decision/investigation.
- **[Lab work]** — needs physical bench/instrument time, not further analysis.
- **[Decision]** — a judgement call explicitly left open, usually deferred to the thesis author.
- **[Limitation]** — a known gap, deliberately deprioritised (not an oversight).
- **[Blocked]** — can't proceed in this environment (e.g. missing/unsynced data).
- **[Investigation]** — still actively being chased, no blocker, just not finished.

Last compiled: October 2026 (from `GCMSQuantitation/CONTEXT.md`, `ASTRA/doe/CONTEXT.md`, `UVSwabbing/CONTEXT.md`, `SartoriusBalance/CONTEXT.md`, `ASTRA/README.md`). Updated Oct 7 2026 with findings from a full-repo red-team code review (all items tagged *"Oct 7 2026 red-team review"* below) — those items have no corresponding `CONTEXT.md` session entry yet; file:line references are given directly instead.

- **[Limitation]** Explosive/keyword detection (`ExplosivesInterpolScopusSearch/Code/02_Interpol_Data_Prep.R`, `03_Scopus_Data_Prep.R`) uses plain `grep()` with no word-boundary anchoring, so short acronym entries in `ReferenceLists/ExplosiveDatabase.csv` (`NC`, `NG`, `NT`, `TEX`) match as substrings inside ordinary English words ("amoNG", "coNTent", "conTEXt") — likely inflating those specific explosives' mention counts in every count/year/country breakdown.
- **[Bug]** Both projects hardcode a `2001-2022` year filter in multiple scripts (`02_Interpol_Data_Prep.R`, `14_`/`15_Scopus_Explosive_Year_Figure.R`, `SamplingInterpolScopusSearch/GlobalCode.R`, `Interpol Sampling Keywords.R`), but the underlying Scopus/INTERPOL source files already contain real 2023 (and INTERPOL 2024) records, confirmed by direct inspection — the most recent year(s) of already-collected data are silently dropped from every by-year trend figure with no comment explaining the cutoff.
- **[Limitation]** Diacritic-safe city/country matching (`removeDiacritics()`) is computed in both projects but the variable actually used downstream (`...CountryListUnique`) matches on the raw accented string instead — countries with accented affiliation names (e.g. Côte d'Ivoire) are silently undercounted in every country-affiliation figure.
- **[Limitation]** Deduplication is inconsistent and generally weak across both projects: `02_Interpol_Data_Prep.R` dedupes on raw, not-yet-normalized Title (before case/punctuation cleaning); `03_Scopus_Data_Prep.R` dedupes on the whole row with no key column, which is close to a no-op across the 3 separate Scopus export files; `SamplingInterpolScopusSearch/GlobalCode.R`'s Interpol dedup has the same whole-row weakness. Net effect is likely some double-counting of cross-file duplicate records in per-year publication counts.
